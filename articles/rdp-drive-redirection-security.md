## はじめに

リモートデスクトップ（RDP）は、離れたWindowsを手元のPCから操作するための便利な仕組みです。ただし、RDPは画面とキーボード入力だけを転送するものではありません。設定によっては、手元PCのドライブ、クリップボード、プリンターなどを接続先と共有します。

この共有機能は、接続先が信頼できる間は便利です。しかし、接続先そのものが侵害されていた場合、便利な経路がローカルPCへの読み書き経路になります。

この記事では、2026年10月に公表された「お名前.com デスクトップクラウド」の不正アクセス事案を入口として、次の点を整理します。

- Active Directory環境で高権限アカウントを守る理由
- RDPドライブリダイレクトの仕組み
- 通信が暗号化されていても残るリスク
- 利用者側と管理者側で取れる対策

## まず、確認済みの事実と推測を分ける

セキュリティ事案を読むときは、公式に確認された事実と、第三者の主張や技術的に成立し得る仮説を混ぜないことが重要です。

2026年10月24日の公式発表では、次の内容が公表されています。

- 一部の利用者サーバーに不正なプログラムが設置された
- 影響の可能性があるサーバーは26,739件
- この数字は侵害や情報取得が確認された件数ではなく、対象となり得る件数
- サーバー内の取引口座ログイン情報などが取得され、不正利用された可能性がある
- 個別の取得・不正利用の有無と範囲は調査中

また、同社はパスワード変更に加えて、既存セッションの切断、取引履歴の確認、端末のフルスキャン、バックアップなどを案内しています。

この記事は、顧客PCへの侵入経路を事案の確定事実として説明するものではありません。RDPの一般的な技術仕様として、どのような条件でローカル資源が接続先から利用可能になるかを扱います。

## RDPは「画面転送だけ」ではない

RDP接続では、ローカルPCの資源を接続先へリダイレクトできます。

- ローカルドライブ
- クリップボード
- プリンター
- スマートカード
- マイクやカメラなどのデバイス

Microsoftは、ドライブリダイレクトを有効にすると、リモートコンピューターがローカルドライブ上のファイルを読み書きできると説明しています。侵害済みの接続先は、文書や資格情報を含むファイルを盗んだり、スタートアップフォルダーなどへ不正ファイルを書き込んだりする可能性があります。

接続先から見たリダイレクト済みドライブは、環境によって次のような名前で表示されます。

```text
\\tsclient\C
```

重要なのは、ローカルのCドライブをインターネット全体へ公開しているわけではない点です。RDPセッション内の仮想チャンネルを通して、接続先からローカル側へファイル操作を要求します。

## 危険が成立するまでの条件

RDPを使っただけで、必ずローカルPCのファイルが盗まれるわけではありません。少なくとも、次の条件が重なる必要があります。

```text
接続先サーバーが攻撃者に操作されている
  + 利用者がそのサーバーへRDP接続している
  + ドライブリダイレクトが許可されている
  + 攻撃者が利用者のRDPセッションを悪用できる
  = ローカルドライブへ到達する経路が生じ得る
```

逆に言えば、ドライブリダイレクトを無効化すれば、この経路を一つ閉じられます。クライアント画面のチェックを外すだけでなく、組織ではグループポリシーやMDMで禁止できます。

## 暗号化されていても安全とは限らない

RDP通信の暗号化は、通信経路上での盗聴や改ざんを防ぐために重要です。ただし、接続先サーバー自体が侵害されている場合、暗号化は接続先からの正規形式のファイル要求を止めません。

これは、配送中の箱を強固に保護しても、受取人が攻撃者なら中身を守れないのと同じです。

したがって、次の2つは別の対策として考える必要があります。

1. 通信経路を保護する
2. 接続先を信頼できる状態に保ち、共有範囲を最小化する

## Active Directoryと横展開

Active Directory（AD）は、組織内のユーザー、コンピューター、グループ、権限を一元管理するための仕組みです。ADを利用すること自体が危険なのではありません。

問題になるのは、高権限アカウントの利用範囲が広すぎる場合です。Domain Adminsなどの資格情報を攻撃者に取得されると、ネットワーク到達性やログオン権限の範囲内で、別のサーバーへ侵害を広げる「ラテラルムーブメント」が起きる可能性があります。

Microsoftも、特権グループのメンバーを最小限にし、管理者アカウントと通常利用アカウントを分け、管理者がサインインできる端末を制限することを推奨しています。

```text
1台の侵害
  -> 高権限資格情報の取得
  -> 管理可能な別サーバーへ移動
  -> 顧客・業務環境へ被害が拡大
```

ただし、1台が侵害されたら自動的に全台が侵害されるわけではありません。ネットワーク分離、ログオン先制限、最小権限、監視によって移動範囲を狭められます。

## パスワードとセッションは別物

侵害後にパスワードを変更しても、既存のログインセッションが直ちに失効するとは限りません。セッションは、認証済みの状態を一定期間維持する仕組みだからです。

公式案内でも、パスワード変更済みの場合を含め、接続中の全セッションを切断するよう呼びかけています。

インシデント対応では、次をセットで扱う必要があります。

- パスワード・秘密鍵などの資格情報を変更する
- 既存セッションやトークンを失効させる
- 多要素認証を有効化する
- ログイン履歴・取引履歴を確認する
- 端末とサーバーを調査する

## 利用者側の確認事項

### 平常時

1. 不要なドライブ共有をオフにする
2. 不要なクリップボード共有をオフにする
3. RDPファイルの接続先と発行元を確認する
4. 共有を要求されているローカル資源を接続前に確認する
5. 接続先で使う認証情報をローカルの重要アカウントと使い回さない

Microsoftは2026年4月以降の更新で、RDPファイルが要求するリダイレクトを既定で無効化し、利用者が明示的に許可する警告を強化しました。ただし、手動接続や組織ポリシーでは動作が異なるため、更新済みであることだけに依存してはいけません。

### 侵害が疑われる場合

1. 公式サイトから最新情報を確認する
2. 不審なRDP接続を終了する
3. 関連する全セッションを切断する
4. 資格情報を安全な端末から変更する
5. 端末をフルスキャンする
6. 重要データを安全な場所へバックアップする
7. ログイン履歴・取引履歴・残高を確認する
8. 不審なメールのリンクや添付ファイルを開かない

## 管理者側の確認事項

- Domain Adminsなどのメンバーを最小限にする
- 日常利用と管理作業でアカウントを分ける
- 管理者のログオン先を管理端末へ限定する
- 顧客環境・管理環境・通常業務環境をネットワーク分離する
- 不要なRDPリダイレクトをグループポリシーで禁止する
- 管理者ログオンとサーバー間通信を監視する
- 資格情報変更とセッション失効をインシデント手順へ含める
- RDPファイルを組織で配布する場合は署名し、信頼する発行元を制限する

## 学んだこと

- クラウドに保存したデータだけでなく、クラウドへ接続・共有したローカル資源も保護対象になる
- 暗号化は重要だが、侵害済みの接続先を安全には戻さない
- ADは危険な仕組みではなく、権限の広さと運用方法が被害範囲を左右する
- パスワード変更とセッション失効は別の作業
- セキュリティ事案では、公式確認済み事項と技術的仮説を分けて読む
